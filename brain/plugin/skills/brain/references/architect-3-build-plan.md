**המטרה:** סדר בנייה שאפשר באמת לבצע, ובריף לכל לבנה שאפשר לבנות ממנו בשיחה נפרדת.

## א5. תוכנית בנייה

### תנאים מוקדמים - לפני הכל

לפעמים לבנים חסומות בדברים שהם לא לבנה: החלטה של הלקוח, מידע שחסר, כלי שעוד לא
בנוי, הכרעה של סוכן אחר. **לפני הגרסה המינימלית - פרק "תנאים מוקדמים":**

```markdown
## תנאים מוקדמים

| # | מה | למה חוסם | מי | פותח את |
|---|---|---|---|---|
| ת-א | <החלטה / מידע / כלי חסר> | <...> | <המפעיל / הלקוח / שיחת הבנייה של X> | לבנים <#> |

**מה אפשר להתחיל עכשיו:** <התנאי או הלבנה הראשונים שבידינו>
```

**לבנה חסומה על כלי שעוד לא בנוי** ← בודקים אם יש תחליף בדיקה 🧪 (למשל קובץ נתונים
מסומן) שמאפשר לבנות ולבדוק כבר עכשיו את הלבנים שתלויות בה. יש ← **מסלול מקביל, לא
המתנה.** כשהכלי האמיתי מוכן - מחליפים את ה-🧪 ובודקים שוב.

### הסדר

1. **גרסה מינימלית קודם:** הקבוצה הכי קטנה של לבנים שמייצרת את התוצר פעם אחת,
   מקצה לקצה - גם אם בחלק מהלבנים אדם עושה ידנית בינתיים.
2. **לבנה שחוסמת אחרות - לפני הן.** מקור אמת לנתונים לפני הסוכן שמשתמש בהם.
3. **כל השאר - אחרי שהגרסה המינימלית עובדת.** לבנה אחת בכל פעם.

### השער

מציג למפעיל: התנאים המוקדמים, הגרסה המינימלית, הסדר, והעוזר לכל לבנה.
> "הגרסה המינימלית: <לבנים>. אחריה: <לבנים>. לפני הכל צריך <תנאים>. נמשיך או לחדד?"

**הסדר וההיקף הם החלטה של המפעיל** - לא של האדריכל.

### הבריפים - רק אחרי השער, ורק לגרסה המינימלית

בריף שנכתב לפני שהמפעיל אישר היקף - נזרק אם הוא משנה. ובריף ללבנה שתיבנה בעוד חודשים -
מתיישן. **שאר הלבנים מקבלות בריף כשהן עולות לתור.**

**המבחן:** AI אחר, בשיחה חדשה, בונה מהבריף את הלבנה - בלי לקרוא את השיחה הזו.

```markdown
# <שם הלבנה> - בריף לבנייה

> מתוך: `plan.md` בתיק <slug> · לבנה <#>
> **הקשר:** <הלקוח במשפט> · <המשימה במשפט> · <איפה הלבנה הזו בתוכה>

| | |
|---|---|
| **מה היא עושה** | משפט אחד |
| **קלט** | מה נכנס, מאיפה, באיזה פורמט |
| **פלט** | מה יוצא, לאן |
| **הכלי** | סקיל / pipeline / סוכן שותף / משימה לאדם / ... - ולמה (תשובות העץ) |
| **איפה נבנה** | נתיב בריפו |
| **העוזר** | מי מנחה את הבנייה (א6) |
| **מה קיים לשימוש** | נתיבים - מה מרחיבים, מה משתמשים |
| **חשבונות ועלויות** | מה צריך, ומי משלם (חוק ברזל 12) |
| **איך נדע שעובד** | מקרה בדיקה אחד לפחות - קלט אמיתי ← הפלט הצפוי |
| **מה היא לא עושה** | גבולות |
| **חסום על** | תנאים מוקדמים או לבנים שחייבים לפניה - או "כלום" |
```

### המסירה לבנייה - `handoff-to-build.md`

**בסוף א5 האדריכל עוצר.** הבנייה נעשית בשיחות נפרדות, ולפעמים מחכה לתנאים שלא בידיו.
קובץ המסירה הוא מה ששיחות הבנייה מקבלות, ומה שממנו ממשיכים:

```markdown
# <שם> - מסירה לבנייה

> מהמוח, תיק <slug> · <תאריך>

## המשימה
<התוצר, הקלט, המדדים - מ-א1>

## מפת המשימה
<א1-א8 עם סטטוס>

## תנאים מוקדמים
<הטבלה, ו"מה אפשר להתחיל עכשיו">

## הגרסה המינימלית - לפי הסדר
| צעד | לבנה | הכלי | העוזר | בריף |

**ידני בינתיים:** <מה אדם עושה עד שהלבנה תיבנה>

## אחרי הגרסה המינימלית
<הסדר>

## פתוח
| מה | סימון | איפה |

## השלכות על סוכנים אחרים
<מה, ולאיזו שיחה זה עובר>

## איך ממשיכים
> "המוח, נמשיך עם <slug>"
```

## א6. בנייה עם עוזר - הניתוב

| הכלי | מי מנחה את הבנייה היום | איך |
|---|---|---|
| מסלול סוכן המכירות | המוח - `stage-0-open-case.md` והלאה | מאותו תיק |
| **הרחבה של סוכן קיים** | **שיחת הבנייה של אותו סוכן**, עם העוזר שלו | הבריף עובר לשם. לא נוגעים בו מהתיק (חוק ברזל 8) |
| pipeline חדש | מעיין (`/maayan-lite:maayan`) | בשיחה נפרדת, עם הבריף |
| סוכן שותף חדש | אליאב (`/eliav-lite:eliav-builder`) | בשיחה נפרדת, עם הבריף |
| מסך או דף | עדי (`/adi-lite:adi`) מאפיינת, ואז בנייה | בשיחה נפרדת, עם הבריף |
| אסטרטגיה, שוק, קהל | נתן (`/natan-gen:natan`) | כמו בשלב 2 של המסלול |
| סקיל בודד | `skill-creator`, או ישירות | עם הבריף |
| טבלה, סקריפט | ישירות | עם הבריף |
| משימה לאדם | האדם עצמו | המפעיל מעביר לו את הבריף |

**כל לבנה - בשיחה נפרדת.** השיחה מקבלת את הבריף, בונה, ומסתיימת בקובץ מסירה לתיק.
האדריכל מעדכן את `plan.md`: לבנה ✅ / 🔧 / ⬜ / 🔴.

**אחרי כל שימוש בעוזר** - שורה ב-`brain/helpers/<תחום>.md`:
מה עבד, מה הפריע, מה עוזר משלנו יעשה אחרת. כך נבנים העוזרים שלנו (הכרעה 14).

## א7. פינקי - עוד לא נבנה

עד שייבנה: לכל לבנה יש בבריף "איך נדע שעובד". המפעיל מריץ את מקרה הבדיקה לפני
שהלבנה מסומנת ✅.

## א8. מסירה ולקחים

כשהגרסה המינימלית עובדת:
- `handoff.md` בתיק: מה נבנה, איפה כל לבנה, איך מפעילים, מה עוד פתוח.
- לקחים ← `lessons.md` בתיק (על ההוראות - לשיחת הבנייה; על הלקוח - בתיק).
- נכס חדש ← שורה ב-מצאי הנכסים של המפעיל, אם יש.
